## Resumen
Para una RTX 3060 Ti (8 GB) en Windows 11, a septiembre de 2026, el setup recomendado es: **ComfyUI Portable** como interfaz (por su API HTTP nativa con workflows en JSON, que es lo que Claude Code va a automatizar por lotes, por su gestión de VRAM y por su soporte día cero de modelos nuevos), con **FLUX.2 [klein] 4B** (Apache 2.0, 4 pasos, GGUF Q8_0 de 4,3 GB) como modelo principal para retratos, escenas y fondos, y una **finetune de SDXL orientada a fantasía pintada (ZavyChromaXL o DreamShaper XL) + LoRA de estilo painterly** como modelo secundario para el look pictórico, para objetos con transparencia nativa (LayerDiffuse) y para aprovechar el ecosistema de LoRAs/ControlNet más grande. Z-Image Turbo (6B, Apache 2.0) queda como alternativa rápida; Chroma1-HD como alternativa de calidad pero lenta en 8 GB; Qwen-Image 2.0 solo si hace falta texto dentro de la imagen. Flux.2 dev, klein 9B, Flux.1 dev (no comerciales), HiDream O1 (>8 GB) y SD 3.5 Medium (ecosistema débil) quedan descartados.

Herramientas auxiliares: ComfyUI-GGUF (city96), ComfyUI-RMBG con pesos BiRefNet (MIT) y Lucida (fine-tune de BiRefNet para ilustraciones y logos) para recorte con alfa, ComfyUI-layerdiffuse para alfa nativo en SDXL, Ultimate SD Upscale + Real-ESRGAN/4x-UltraSharp para ampliar fondos, ai-toolkit (Ostris) para entrenar un LoRA de estilo propio, y un script Python contra `POST /prompt` para generar en lote desde un manifiesto de assets.

Para el logo, la recomendación es no confiar la tipografía final a un modelo de difusión: generar el emblema con Klein/SDXL, recortarlo con BiRefNet/Lucida y componer el título con una fuente libre (SIL OFL) en SVG/CSS, que además es traducible. Los tiempos por imagen en la 3060 Ti son estimaciones extrapoladas (no encontré benchmarks directos de esta tarjeta) y conviene hacer un bake-off de un día con 20 prompts fijos antes de fijar el modelo principal.

## Hallazgos
## (a) Interfaz: ComfyUI, con Forge Neo como opcional para iterar a mano

**Estado del panorama (2026)**
- **ComfyUI**: servidor headless por defecto; la UI es solo un cliente. Cualquier cliente HTTP hace `POST http://127.0.0.1:8188/prompt` con el workflow en "API format" (exportado desde el menú con Dev Mode activado) y recupera salidas con `/history` y `/view`; hay WebSocket para progreso. Es el único de los cuatro que trata el workflow como un artefacto JSON versionable en el repo, ideal para que Claude Code genere lotes reproducibles (mismo grafo, cambian prompt/seed/nombre de salida). Soporte de modelos nuevos en horas/días (Flux.2 klein, Z-Image Base, Qwen-Image 2.0, HiDream O1, Chroma tuvieron soporte nativo o day-0). Desde el 1 de marzo de 2026 el "Dynamic VRAM" viene activado por defecto en NVIDIA/Windows (se puede apagar con `--disable-dynamic-vram`), lo que ayuda en 8 GB con encoders de texto grandes. Flags útiles: `--lowvram` (para modelos de 12B como Flux.1), `--use-pytorch-cross-attention`. Curva de aprendizaje alta para humanos, pero irrelevante si quien arma los grafos es Claude Code.
- **Forge Neo** (rama `neo` de Haoming02/sd-webui-forge-classic): fork de A1111, solo NVIDIA, releases casi mensuales en 2026. En febrero de 2026 soportaba Flux.2-Klein 4B/9B, Flux Kontext, Qwen-Image, Z-Image, Wan 2.2, Lumina, Chroma1-HD y Nunchaku. Tiene API REST estilo A1111. Más rápido que ComfyUI en txt2img simple (~5,5 s vs ~7,8 s SDXL en una 4070 Ti según offlinecreator), pero sigue a ComfyUI "de días a semanas" en modelos nuevos y las pipelines complejas (recorte + upscale + guardado con nombre) son incómodas. Útil solo como segunda herramienta para probar LoRAs a mano compartiendo la carpeta de modelos.
- **SwarmUI**: front-end de formularios que usa ComfyUI como motor (hereda soporte de modelos); agrega una capa que no aporta nada si la automatización va por la API de Comfy.
- **InvokeAI**: mejor lienzo de inpainting/outpainting; agregó Flux.2 Klein a principios de 2026 y FP8 para Z-Image Turbo; pero según comparativas de 2026 ComfyUI es "medible-mente más rápido" en Flux y en tarjetas de 8-12 GB. Solo tendría sentido como herramienta de retoque manual puntual.

**Veredicto**: ComfyUI Portable (zip oficial con Python embebido, `run_nvidia_gpu.bat`), ComfyUI-Manager para nodos, y todo el pipeline como JSON en el repo del juego.

Hay guías de Z-Image LoRA en 8 GB (RunComfy) y de klein 4B "sin cuantización forzada"; para SDXL, kohya_ss en 8 GB es rutina. No pude verificar tiempos de entrenamiento en una 3060 Ti.

## (d) Upscaling y limpieza en 8 GB

- **Modelos ESRGAN puros** (4x-UltraSharp, Real-ESRGAN x4plus, 4x-NMKD-Siax): 2-4 GB de VRAM, segundos por imagen, sin difusión. Suficiente para fondos 1344×768 → 2688×1536 y luego bajar a 1920 px. Ojo: 4x-UltraSharp se distribuye con licencia CC BY-NC-SA según su autor (no verificado en esta sesión); Real-ESRGAN es BSD.
- **Ultimate SD Upscale** (nodo ComfyUI_UltimateSDUpscale): tiles de 1024 con img2img al 0,3-0,5 de denoise; en 8 GB funciona con SDXL o klein 4B; ir 2× → 4× en dos pasos. Solo hace falta para ilustraciones "hero" (portada, escenas clave).
- Limpieza: para retratos, un pase de img2img con denoise 0,2-0,3 en el mismo modelo homogeneiza el trazo; ADetailer/FaceDetailer (Impact Pack) para caras en planos abiertos. Evitar restauradores fotográficos (GFPGAN/CodeFormer) porque "fotografían" un estilo pintado.

## (e) Assets con fondo transparente (objetos, iconos)

- **ComfyUI-RMBG** (1038lab, v3.1.0 del 21-jul-2026): integra RMBG-2.0, BiRefNet (general/portrait/matting/HR 2560²/lite), BEN/BEN2, INSPYRENET, SDMatte, SAM/SAM2/SAM3, GroundingDINO y **Lucida** (fine-tune de BiRefNet para objetos transparentes, texto/logos, glow/VFX e ilustraciones: exactamente iconos y objetos de fantasía). Salida con canal alfa y máscara. Repo GPL-3.0 (afecta al nodo, no a tus PNG).
- **Licencias de pesos**: BiRefNet original = **MIT** (default seguro comercial; ComfyUI también lo trae nativo como subgrafo "Remove Background (BiRefNet)" con `birefnet.safetensors` en `models/background_removal/`). **RMBG-2.0 de BRIA = CC BY-NC 4.0**, requiere licencia comercial: NO usarlo. Lucida/BEN2: verificar licencia en su ficha antes de usar.
- **rembg** (u2net/isnet) sigue funcionando por CLI/Python y sirve para lotes fuera de Comfy, pero BiRefNet recorta mejor bordes finos.
- **Alfa nativo**: **LayerDiffuse** (ComfyUI-layerdiffuse, huchenlei) solo soporta SD1.5/SDXL; genera RGBA directo (ideal para objetos e iconos sin halo de fondo). No hay soporte LayerDiffuse para Flux/klein/Z-Image a la fecha; para esos modelos: generar sobre fondo liso neutro contrastante y recortar con BiRefNet/Lucida.
- Receta práctica: prompt "isolated object, centered, plain flat gray background, no shadow" → BiRefNet/Lucida → PNG con alfa → exportar WebP con alfa a 256/512 px.

## (f) Logo y tipografía

- Ningún modelo de 8 GB produce tipografía final fiable: Qwen-Image es el mejor en texto (y Z-Image Turbo supera a klein en ortografía en pruebas), pero en 8 GB Qwen corre en Q2/Q3 con degradación. Klein 4B renderiza texto "legible" pero con errores.
- Recomendación: el logo = emblema/marca (escudo, espada, sello, dragón estilizado) generado con klein/SDXL + recorte BiRefNet/Lucida, y el nombre del juego compuesto con una fuente libre bajo SIL OFL desde Google Fonts (p. ej. Cinzel, Cinzel Decorative, Uncial Antiqua, MedievalSharp, IM Fell) en SVG/CSS. Ventajas: nítido a cualquier tamaño, traducible (decisión 15), sin depender de la generación. Si se quiere un "wordmark pintado", usar el texto vectorial como ControlNet/imagen de referencia en img2img SDXL con denoise 0,4-0,5 para darle textura.
- Iconos de UI (dados, inventario, estados): más consistente generar un set con el mismo prompt base + LoRA de estilo y seed fija que buscar iconos sueltos; para iconos monocromos, mejor SVG a mano/Lucide.

## Configuración de lote sugerida (para que Claude Code la implemente)

- Manifiesto `assets.json` en el repo: `{id, tipo (retrato|fondo|objeto|escena), prompt, negativo, ancho, alto, seed, modelo, lora}`.
- Script Python: carga el workflow API-format, sustituye prompt/seed/tamaño/nombre de salida, `POST /prompt`, espera por WebSocket, copia `output/<id>.png`, corre rembg si `tipo=objeto`, upscale si `tipo=fondo`, convierte a WebP. Todo determinista por seed → regenerable.
- Tamaños: retratos 832×1216 (→ 512×768 web), fondos 1344×768 (→ 2× upscale → 1920 px), objetos 1024×1024 (→ 512), escenas 1216×832.
- Requisitos de sistema: 32 GB de RAM recomendados (los encoders Qwen3/T5 se descargan a RAM en 8 GB), SSD NVMe, driver NVIDIA reciente.

## Plan de instalación resumido (Windows 11)

1. Actualizar driver NVIDIA (Game Ready o Studio). Verificar RAM (ideal 32 GB) y ≥60 GB libres en SSD.
2. Bajar **ComfyUI Portable** (docs.comfy.org/installation/comfyui_portable_windows), descomprimir en `C:\ComfyUI`, ejecutar `run_nvidia_gpu.bat`. En Settings activar Dev Mode (para "Save (API format)").
3. Instalar **ComfyUI-Manager**; desde él: `ComfyUI-GGUF` (city96), `ComfyUI-RMBG`, `ComfyUI_UltimateSDUpscale`, `ComfyUI-layerdiffuse`, `ComfyUI-Impact-Pack` (FaceDetailer), opcional `ComfyUI-nunchaku` (INT4 para Z-Image/Flux.1/Qwen).
4. Modelos: `flux-2-klein-4b-Q8_0.gguf` → `models/unet` (o `diffusion_models`); encoder Qwen3-4B fp8/GGUF → `models/text_encoders`; VAE Flux.2 → `models/vae`. `ZavyChromaXL` o `DreamShaper XL` → `models/checkpoints`; LoRA painterly SDXL → `models/loras`; `RealESRGAN_x4plus`/`4x-UltraSharp` → `models/upscale_models`; `birefnet.safetensors` → `models/background_removal` (+ Lucida vía RMBG).
5. Cargar las plantillas oficiales (Flux.2 klein T2I / edit; SDXL) y guardar cada una en API format en `tools/comfy/*.json` del repo.
6. Script `tools/gen_assets.py` (requests + websocket-client) que lee `assets.json` y genera; `tools/post.py` para rembg/upscale/WebP.
7. **Bake-off de 1 día**: 20 prompts fijos (5 retratos, 5 fondos, 5 objetos, 5 escenas) × {klein 4B, SDXL+LoRA, Z-Image Turbo}; elegir principal y fijar LoRA/seed/prompt base como "guía de estilo" en el repo.
8. Si el estilo no converge, entrenar un LoRA de estilo propio con ai-toolkit (klein 4B o Z-Image Base) o kohya (SDXL) con 30-60 imágenes curadas del bake-off.
